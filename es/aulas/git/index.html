Clase 6 · 20 min

Git: la red de seguridad para deshacer cualquier cambio

En una tarea, el agente puede cambiar diez archivos a la vez. Sin historial, no sabes qué cambió ni cómo volver atrás. Con Git, cada versión buena queda guardada con fecha y explicación, y el cambio que no aprobaste se revierte con un comando.

Empezar la clase

En esta clase vas a

  1. 1Empezar el historial solo en la carpeta del proyecto
  2. 2Leer git status y git diff antes de guardar
  3. 3Guardar una versión con un mensaje que diga qué cambió
  4. 4Volver un archivo con git restore y deshacer una versión con git revert

Objetivo: guardar versiones con status, add, diff y commit, y deshacer un cambio del agente con git restore, sin pánico.

01 · Cambió, separó, guardó

Las tres etapas de un archivo en Git. Haz clic en cada una.

Clase 601 · Cambió, separó, guardóLas tres etapas de un archivo en Git. Haz clic en cada una.

Regla de oro: commit antes de pedir un cambio grande
1/5

En la carpeta

El agente creó o cambió archivos. git status muestra cada uno: "Untracked files" son los que Git todavía no sigue; "Changes not staged" son cambios que aún no se han separado.

Desplázate por la página: cada etapa de abajo enciende su parte del diagrama.

  1. 1/5

    En la carpeta

    El agente creó o cambió archivos. git status muestra cada uno: "Untracked files" son los que Git todavía no sigue; "Changes not staged" son cambios que aún no se han separado.

  2. 2/5

    Separado

    git add con el nombre del archivo separa solo ese para la próxima versión (Git lo llama staging). git diff --cached muestra, línea por línea, lo que va a entrar.

  3. 3/5

    Versión guardada

    El commit engrapa lo que se separó. El mensaje es el pie de foto: verbo y objeto, como "Acrescenta seção de contato". "update" no dice nada dentro de un mes.

  4. 4/5

    Volver

    Cambio aún no guardado: git restore devuelve el archivo a la última versión guardada (y descarta lo que cambió). Versión ya guardada: git revert crea una versión nueva que deshace la anterior, sin borrar la historia.

  5. 5/5

    El ciclo con el agente

    Commit antes de pedir. El agente cambia. Tú miras con status y diff. Te gustó: add y commit. No te gustó: restore. Cada versión buena se vuelve un punto de regreso.

Git funciona solo en tu computadora, sin internet. GitHub es otro paso, opcional (clase 8).

02 · Del git init al primer deshacer

Haz clic en cada etapa.

1. Empezar el historial

Dentro de meu-primeiro-agente, git init crea el historial. Nunca en toda tu carpeta personal.

git config user.name y user.email, sin --global, dicen quién guarda, solo en este proyecto. El correo aparece en cada versión y queda visible si la carpeta se publica.

RespondeInitialized empty Git repository in …\meu-primeiro-agente\.git\

2. Mirar antes

git status dice en qué etapa está cada archivo. Ejecútalo siempre antes de separar cualquier cosa.

Aquí el .gitignore de la clase 5 demuestra su valor: el .env no aparece en la lista.

BuscaAGENTS.md, README.md, .gitignore, .env.example… y ningún .env.

3. Guardar

Para aprender, nombra los archivos en el git add. El atajo git add . separa todo lo que no está ignorado, incluida la nota personal olvidada en la carpeta.

git log --oneline muestra la lista corta de las versiones, una por línea.

Buen mensajeCrea README, AGENTS.md y lista de lo que no se guarda

4. Deshacer

Solo en el archivo, sin guardar: git restore archivo. En una versión guardada: git revert con el código de la versión, que aparece en el log.

Revisa el archivo abierto, no solo la respuesta de la terminal.

Fe de erratas, no tachónEl revert corrige y deja las tres versiones en el historial.

03 · Los comandos de Git

En la carpeta meu-primeiro-agente. Cambia lo que esté entre < >.

cmd · empezar y decir quién eres (solo en esta carpeta)
cd %USERPROFILE%\projetos\meu-primeiro-agente
git init
git config user.name "<Seu Nome>"
git config user.email "<seu@email.com>"
git status
cmd · mirar, separar y guardar la primera versión
git add README.md AGENTS.md .gitignore .env.example index.html
git diff --cached
git commit -m "primeira versão"
git log --oneline
cmd · después de que el agente cambió algo
git status
git diff
cmd · no te gustó: devuelve el archivo
git restore index.html
git status
cmd · si te gustó: guarda la nueva versión
git add index.html
git commit -m "<lo que cambió, con verbo>"
cmd · deshacer una versión ya guardada
git log --oneline
git revert <código de la versión>
Simulación: ejemplo ilustrativo
On branch master
No commits yet
Untracked files:
  (use "git add <file>..." to include in what will be committed)
        .env.example
        .gitignore
        AGENTS.md
        README.md
        index.html

"Untracked files" = fuera del historial. El .env no está en la lista: el .gitignore funcionó.

  • Untracked files: archivos que Git todavía no sigue.
  • Changes to be committed: separados, entran en la próxima versión.
  • Changes not staged: cambiaron, pero no fueron separados.
  • nothing to commit, working tree clean: nada cambió desde la última versión.
  • git init en la carpeta personal: Git empieza a mirar Documentos, Descargas, todo. Ejecuta cd antes y revisa la ruta.
  • Saltarte Git: el primer cambio malo del agente se convierte en retrabajo manual.
  • "Please tell me who you are": faltó el git config de nombre y correo.

04 · Ensaya: guardar, estropear y volver

El agente va a cambiar el index.html en el camino.

Misiones

  1. 1Empieza el historial en esta carpeta.
  2. 2Mira el estado de los archivos.
  3. 3Separa todo lo que no está ignorado.
  4. 4Guarda la primera versión con el mensaje primeira versão.
  5. 5El agente reescribió la página y no te gustó. Mira el estado.
  6. 6Devuelve el index.html a la última versión guardada.

E11 · La red de seguridad
20 min
git init, config, status, add y commit. Pídele al agente un cambio grande en la página y, si no te gusta, vuelve con git restore.
Listo cuando: deshiciste un cambio del agente con un comando, y git status dice "working tree clean".
E12 · Tres versiones con leyenda
15 min
Pide dos cambios pequeños y guarda cada uno con un mensaje que diga qué cambió. Después deshaz el último con git revert.
Listo cuando: git log --oneline muestra las versiones con mensajes claros, incluida la del revert, y la página volvió a como estaba.
