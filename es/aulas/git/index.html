Clase 6 · 20 min

Git: la red de seguridad para deshacer cualquier cambio

En una tarea, el agente puede cambiar diez archivos a la vez. Sin historial, no sabes qué cambió ni cómo volver atrás. Con Git, cada versión buena queda guardada con fecha y explicación, y el cambio que no aprobaste se revierte con un comando.

Empezar la lección

En esta lección vas a

  1. 1Empezar el historial solo en la carpeta del proyecto
  2. 2Leer git status y git diff antes de guardar
  3. 3Guardar una versión con un mensaje que diga qué cambió
  4. 4Volver atrás un archivo con git restore y deshacer una versión con git revert

Objetivo: guardar versiones con status, add, diff y commit, y deshacer un cambio del agente con git restore, sin pánico.

01 · Cambió, separó, guardó

Las tres etapas de un archivo en Git. Haz clic en cada una.

Clase 601 · Cambió, separó, guardóLas tres etapas de un archivo en Git. Haz clic en cada una.

Regla de oro: haz un commit antes de pedir un cambio grande
1/5

En la carpeta

El agente creó o cambió archivos. git status muestra cada uno: "Untracked files" son los que Git todavía no sigue; "Changes not staged" son cambios que aún no se separaron.

Desplázate por la página: cada etapa ilumina su parte del diagrama.

  1. 1/5

    En la carpeta

    El agente creó o cambió archivos. git status muestra cada uno: "Untracked files" son los que Git todavía no sigue; "Changes not staged" son cambios que aún no se separaron.

  2. 2/5

    Separado

    git add con el nombre del archivo separa solo ese archivo para la próxima versión (Git lo llama staging). git diff --cached muestra, línea por línea, lo que se incluirá.

  3. 3/5

    Versión guardada

    El commit sujeta lo que se separó. El mensaje es el pie de foto: verbo y objeto, como "Agrega sección de contacto". "update" no dice nada dentro de un mes.

  4. 4/5

    Volver

    Cambio aún sin guardar: git restore devuelve el archivo a la última versión guardada (y descarta los cambios). Versión ya guardada: git revert crea una versión nueva que deshace la anterior, sin borrar el historial.

  5. 5/5

    El ciclo con el agente

    Haz un commit antes de pedir el cambio. El agente modifica. Revisa con status y diff. Si te gusta: add y commit. Si no: restore. Cada versión buena se convierte en un punto de retorno.

Git funciona solo en tu computadora, sin internet. GitHub es otro paso, opcional (clase 8).

02 · De git init al primer deshacer

Haz clic en cada etapa.

1. Iniciar el historial

Dentro de meu-primeiro-agente, git init crea el historial. Nunca lo hagas en toda tu carpeta personal.

git config user.name y user.email, sin --global, indican quién guarda los cambios, solo en este proyecto. El correo aparece en cada versión y queda visible si publicas la carpeta.

RespondeInitialized empty Git repository in …\meu-primeiro-agente\.git\

2. Revisar antes

git status indica en qué etapa está cada archivo. Ejecútalo siempre antes de separar cualquier cosa.

Aquí se demuestra para qué sirve el .gitignore de la clase 5: .env no aparece en la lista.

BuscaAGENTS.md, README.md, .gitignore, .env.example… y ningún .env.

3. Guardar

Para aprender, indica los archivos en git add. El atajo git add . separa todo lo que no está ignorado, incluso esa nota personal que olvidaste en la carpeta.

git log --oneline muestra una lista breve de las versiones, una por línea.

Un buen mensajeCrea README, AGENTS.md y una lista de lo que no debes guardar

4. Deshacer

Solo en el archivo, sin guardar: git restore archivo. En una versión guardada: git revert con el código de la versión, que aparece en el log.

Revisa el archivo abierto, no solo la respuesta de la terminal.

Fe de erratas, no borrónrevert corrige y deja las tres versiones en el historial.

03 · Los comandos de Git

En la carpeta meu-primeiro-agente. Reemplaza lo que esté entre < >.

cmd · empezar y decir quién eres (solo en esta carpeta)
cd %USERPROFILE%\projetos\meu-primeiro-agente
git init
git config user.name "<Seu Nome>"
git config user.email "<seu@email.com>"
git status
cmd · iniciar e decir quién eres (solo en esta carpeta)
git add README.md AGENTS.md .gitignore .env.example index.html
git diff --cached
git commit -m "primeira versão"
git log --oneline
cmd · revisar, separar y guardar la primera versión
git status
git diff
cmd · después de que el agente hizo un cambio
git restore index.html
git status
cmd · no te gustó: restaura el archivo
git add index.html
git commit -m "<o que mudou, com verbo>"
cmd · deshacer una versión ya guardada
git log --oneline
git revert <código de la versión>
Simulación: ejemplo ilustrativo
On branch master
No commits yet
Untracked files:
  (use "git add <file>..." to include in what will be committed)
        .env.example
        .gitignore
        AGENTS.md
        README.md
        index.html

"Untracked files" = archivos fuera del historial. .env no aparece en la lista: .gitignore funcionó.

  • Untracked files: archivos que Git todavía no rastrea.
  • Changes to be committed: separados, se incluirán en la próxima versión.
  • Changes not staged: cambiaron, pero no están separados.
  • nothing to commit, working tree clean: no cambió nada desde la última versión.
  • git init en la carpeta personal: Git empieza a revisar Documentos, Descargas y todo lo demás. Ejecuta cd antes y comprueba la ruta.
  • Saltarse Git: el primer cambio malo del agente se convierte en trabajo manual.
  • "Please tell me who you are": faltó el git config con el nombre y el correo electrónico.

04 · Ensaya: guarda, estropea y vuelve

El agente cambiará index.html a mitad del proceso.

Misiones

  1. 1Empieza el historial en esta carpeta.
  2. 2Mira el estado de los archivos.
  3. 3Separa todo lo que no está ignorado.
  4. 4Guarda la primera versión con el mensaje primeira versão.
  5. 5El agente reescribió la página y no te gustó. Mira el estado.
