Clase 8 · 20 min

Página en línea y el mismo proyecto en una VPS

Guardar, enviar y poner en línea son tres pasos y tres decisiones. Con una clave SSH y gh, envías el proyecto a GitHub, publicas la página con una dirección que puedes abrir en el celular y llevas la misma carpeta a una VPS, donde el agente trabaja aunque tu computadora esté apagada.

Empezar la lección

En esta lección vas a

  1. 1Crear la clave SSH y entregar solo la pública
  2. 2Crear el repositorio, publicar en Pages y seguir la rutina del push
  3. 3Revisar el destino, el estado, las versiones y los secretos antes de enviar
  4. 4Entrar en la VPS, clonar el proyecto y traer los cambios

Objetivo: conectar la terminal con GitHub mediante una clave SSH, publicar la página en GitHub Pages y clonar el proyecto en una VPS.

01 · Tres lugares, un proyecto

GitHub es el puente entre tu computadora, la página y la VPS.

1/5

Tu computadora

Desplázate por la página: cada etapa ilumina su parte del diagrama.

  1. 1/5

    Tu computadora

    La clave privada nunca sale de aquí. El commit guarda la versión solo en tu computadora; nada va a internet hasta que decidas enviarlo.

  2. 2/5

    GitHub

    El push envía las versiones. Repositorio público: cualquiera puede verlo (y es lo que la página gratuita necesita). Privado: solo tú y quienes invites. Tú eliges al crearlo.

  3. 3/5

    GitHub Pages

    Ponerla en línea es un paso más. Una vez activado Pages, cada push actualiza la página en unos minutos, con una dirección que puedes abrir en el celular.

  4. 4/5

    VPS

    Es como una sala alquilada: el proveedor entrega la máquina; los usuarios, las actualizaciones y los programas quedan a tu cargo. Entras por ssh, navegas usando los nombres de Linux y traes el proyecto de GitHub.

  5. 5/5

    Guardar, enviar, poner en línea

    El commit se queda en tu computadora, el push lo lleva a GitHub y Pages lo pone en línea. La VPS obtiene esa misma versión con git pull. Cada paso es una decisión tuya, con su propia revisión.

La clave pública (.pub) es el candado: va a GitHub y a la VPS. La privada es la llave del llavero: se queda contigo.

02 · Del commit a la página en línea

Haz clic en cada etapa.

1. Clave SSH

ssh-keygen ya viene en Windows 10 y 11. Te hace tres preguntas: dónde guardar la clave y una contraseña adicional, dos veces. Para practicar, puedes presionar Enter en las tres.

Quedan dos archivos en %USERPROFILE%\.ssh: id_ed25519 (privada, nunca sale de ahí) y id_ed25519.pub (pública).

¿Preguntó Overwrite?Ya tienes una clave: responde n y usa la que existe.

2. Conectar gh

Responde: GitHub.com → SSH → elige id_ed25519.pub → Login with a web browser. Copia el código, pégalo en el navegador y autoriza.

ssh -T git@github.com prueba la clave; la primera vez, responde yes.

Respuesta¡Hola SEU-USUARIO! Te autenticaste correctamente.

3. Revisa antes de enviar

Destino: git remote -v muestra adónde va. Estado: git status limpio. Versiones: git log --oneline muestra lo que se enviaría. Secretos: ningún .env en la lista.

Después de enviarlo, el contenido queda disponible para quienes tengan acceso al destino.

PúblicoCualquiera puede verlo. Nada de borradores personales ni claves.

4. En la VPS

ssh root@IP-DA-VPS abre la terminal de la VPS en tu ventana. El inicio de la línea cambia y termina en # o $: fíjate siempre en qué máquina estás antes de cada comando.

Allí: ls en lugar de dir, pwd en lugar de cd solo, y las mayúsculas importan.

Regla de la segunda sesión¿Cambiaste la forma de entrar? Pruébala en una ventana nueva antes de cerrar la que funciona.

03 · Los comandos, en orden

Reemplaza Seu Nome, seu@email.com, SEU-USUARIO e IP-DA-VPS por los tuyos.

cmd · quién eres en Git (para todos los proyectos)
git config --global user.name "Seu Nome"
git config --global user.email "seu@email.com"
git config --global --list
cmd · la clave SSH
ssh-keygen -t ed25519 -C "seu@email.com"
explorer %USERPROFILE%\.ssh
cmd · vincular gh a tu cuenta
gh auth login
ssh -T git@github.com
cmd · crear el repositorio y enviarlo
cd %USERPROFILE%\projetos\meu-primeiro-agente
git status
git branch -M main
gh repo create meu-primeiro-agente --public --source=. --push
cmd · activar GitHub Pages
gh api repos/{owner}/{repo}/pages -X POST -f "source[branch]=main" -f "source[path]=/"
cmd · la rutina de todos los días
git status
git add .
git commit -m "o que mudou"
git push
VPS (Linux) · entrar, clonar y actualizar
ssh root@IP-DA-VPS
mkdir -p ~/projetos
cd ~/projetos
apt update && apt install -y git
git clone https://github.com/SEU-USUARIO/meu-primeiro-agente.git
cd meu-primeiro-agente
ls
git pull
exit
VPS (Linux) · el agente en el servidor
curl -fsSL https://claude.ai/install.sh | bash
cd ~/projetos/meu-primeiro-agente
claude
Simulación: ejemplo ilustrativo
C:\Users\ana> ssh -T git@github.com
Hi ana-exemplo! You've successfully authenticated, but GitHub does not provide shell access.
C:\Users\ana\projetos\meu-primeiro-agente> gh repo create meu-primeiro-agente --public --source=. --push
✓ Created repository ana-exemplo/meu-primeiro-agente on GitHub

Unos minutos después de activar Pages, la página se abre en https://ana-exemplo.github.io/meu-primeiro-agente/.

  • "nothing to commit": la carpeta está vacía o ya está guardada. Compruébalo con dir y git log --oneline.
  • "Name already exists": ya existe un repositorio con ese nombre en tu cuenta. Elige otro.
  • Push rechazado con "fetch first": el repositorio cambió en otro lugar. Ejecuta git pull y luego git push.
  • "No such file or directory" en la VPS: comprueba las mayúsculas y usa Tab para completar.

Alguien te pidió tu clave "para configurar el acceso": solo id_ed25519.pub. id_ed25519, sin .pub, nunca sale de tu computadora.

04 · Ensaya: el proyecto en la VPS

La misma navegación, otros nombres. Fíjate en el inicio de la línea.

Misiones

  1. 1Entra en la VPS como root (la IP de ejemplo es 203.0.113.10).
  2. 2Pregunta dónde estás (en Linux es pwd).
  3. 3Crea la carpeta de proyectos (mkdir -p ~/projetos).
  4. 4Entra en ella.
  5. 5Trae el proyecto de GitHub (usuario ana-exemplo).
  6. 6Entra en la carpeta y lista el contenido (dos comandos: primero cd).
  7. 7Lista lo que llegó (en Linux es ls).
  8. 8Cambiaste algo en Windows e hiciste push. Trae el cambio.
  9. 9Sal de la VPS.

15 min
Crea la clave SSH, ejecuta gh auth login eligiendo SSH y prueba con ssh -T git@github.com.
Listo cuando: La respuesta empieza con "Hi", seguido de tu usuario de GitHub.
E16 · Página publicada
20 min
Revisa los cuatro puntos, crea el repositorio público, activa Pages y luego cambia algo y ejecuta la rutina add, commit y push.
Listo cuando: La página se abre en el celular en https://SEU-USUARIO.github.io/meu-primeiro-agente/ y el cambio aparece después del push.
E17 · El mismo proyecto en la VPS
30 min
En una VPS Ubuntu contratada con tu clave pública, entra con ssh, clona el proyecto, cambia algo en Windows, haz push y tráelo con git pull.
Listo cuando: ls en la VPS muestra los archivos y git pull trajo el cambio hecho en Windows.
