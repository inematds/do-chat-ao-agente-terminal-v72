Lesson 8 · 20 min

Page live and the same project on a VPS

Saving, sending, and putting it live are three steps and three decisions. With an SSH key and gh, you send the project to GitHub, publish the page at an address that opens on your phone, and take the same folder to a VPS, where the agent works even when your computer is off.

Start the lesson

In this lesson you will

  1. 1Create the SSH key and hand over only the public one
  2. 2Create the repository, publish on Pages, and the push routine
  3. 3Check destination, status, versions, and secrets before sending
  4. 4Log in to the VPS, clone the project, and bring in what changed

Goal: connect the terminal to GitHub with an SSH key, publish the page on GitHub Pages, and clone the project on a VPS.

  1. 1/5

    Your computer

    The private key never leaves here. The commit saves the version only on your computer; nothing goes to the internet until you decide to send it.

  2. 2/5

    GitHub

    The push sends the versions. Public repository: anyone can see it (and it's what the free page requires). Private: only you and the people you invite. You choose when you create it.

  3. 3/5

    GitHub Pages

    Putting it online is one extra step. Once Pages is on, every push updates the page within a few minutes, at an address that opens on your phone.

  4. 4/5

    VPS

    A rented room: the provider hands over the machine; users, updates, and programs are up to you. You log in through ssh, move around with Linux names, and bring the project over from GitHub.

  5. 5/5

    Save, send, go live

    The commit stays on your computer, the push takes it to GitHub, and Pages puts it online. The VPS gets the same version with git pull. Each step is your decision, with its own check.

The public key (.pub) is the padlock: it goes to GitHub and to the VPS. The private one is the key on your keyring: it stays with you.

02 · From commit to live page

Click each step.

1. SSH key

ssh-keygen already comes with Windows 10 and 11. It asks three questions: where to save, and an extra password, twice. Enter on all three is fine for practice.

Two files end up in %USERPROFILE%\.ssh: id_ed25519 (private, never leaves there) and id_ed25519.pub (public).

Asked Overwrite?You already have a key: answer n and use the one you have.

2. Connect gh

Answer: GitHub.com → SSH → choose id_ed25519.pub → Login with a web browser. Copy the code, paste it in the browser, and authorize.

ssh -T git@github.com tests the key; the first time, answer yes.

AnswerHi SEU-USUARIO! You've successfully authenticated.

3. Check before sending

Destination: git remote -v shows where it goes. Status: git status is clean. Versions: git log --oneline shows what would go. Secrets: no .env in the list.

Once sent, the content belongs to whoever has access to the destination.

PublicAnyone can see it. No personal drafts and no keys.

4. On the VPS

ssh root@IP-DA-VPS opens the VPS terminal in your window. The start of the line changes and ends in # or $: always check which machine you are on before each command.

There: ls instead of dir, pwd instead of cd on its own, and capital letters matter.

Second session ruleDid you change how you log in? Test it in a new window before closing the one that works.

03 · The commands, in order

Replace Seu Nome, seu@email.com, SEU-USUARIO and IP-DA-VPS with your own.

cmd · who you are in Git (for all projects)
git config --global user.name "Seu Nome"
git config --global user.email "seu@email.com"
git config --global --list
cmd · the SSH key
ssh-keygen -t ed25519 -C "seu@email.com"
explorer %USERPROFILE%\.ssh
cmd · connect gh to your account
gh auth login
ssh -T git@github.com
cmd · create the repository and push
cd %USERPROFILE%\projetos\meu-primeiro-agente
git status
git branch -M main
gh repo create meu-primeiro-agente --public --source=. --push
cmd · turn on GitHub Pages
gh api repos/{owner}/{repo}/pages -X POST -f "source[branch]=main" -f "source[path]=/"
cmd · the everyday routine
git status
git add .
git commit -m "o que mudou"
git push
VPS (Linux) · log in, clone and update
ssh root@IP-DA-VPS
mkdir -p ~/projetos
cd ~/projetos
apt update && apt install -y git
git clone https://github.com/SEU-USUARIO/meu-primeiro-agente.git
cd meu-primeiro-agente
ls
git pull
exit
VPS (Linux) · the agent on the server
curl -fsSL https://claude.ai/install.sh | bash
cd ~/projetos/meu-primeiro-agente
claude
Simulation: illustrative example
C:\Users\ana> ssh -T git@github.com
Hi ana-exemplo! You've successfully authenticated, but GitHub does not provide shell access.
C:\Users\ana\projetos\meu-primeiro-agente> gh repo create meu-primeiro-agente --public --source=. --push
✓ Created repository ana-exemplo/meu-primeiro-agente on GitHub

A few minutes after you turn on Pages, the page opens at https://ana-exemplo.github.io/meu-primeiro-agente/.

  • "nothing to commit": the folder is empty or already saved. Check with dir and git log --oneline.
  • "Name already exists": a repository with that name already exists in your account. Pick another one.
  • Push rejected with "fetch first": the repository changed somewhere else. Run git pull and then git push.
  • "No such file or directory" on the VPS: check capital letters and use Tab to autocomplete.

Someone asked for your key "to set up access": only the id_ed25519.pub. The id_ed25519, without .pub, never leaves your computer.

04 · Rehearse: the project on the VPS

Same navigation, different names. Look at the start of the line.

Missions

  1. 1Log in to the VPS as root (the example IP is 203.0.113.10).
  2. 2Ask where you are (on Linux it's pwd).
  3. 3Create the projects folder (mkdir -p ~/projetos).
  4. 4Go into it.
  5. 5Bring the project over from GitHub (user ana-exemplo).
  6. 6Go into the folder and list its contents (two commands: cd first).
  7. 7List what came over (on Linux it's ls).
  8. 8You changed something on Windows and pushed. Bring the change over.
  9. 9Leave the VPS.
