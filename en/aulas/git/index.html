Lesson 6 · 20 min

Git: the safety net for undoing any change

In a single task, the agent can change ten files at once. Without a history, you don't know what changed or how to go back. With Git, every good version is kept with a date and an explanation, and a change you didn't approve goes back with one command.

Start the lesson

In this lesson you will

  1. 1Start the history only in the project folder
  2. 2Read git status and git diff before saving
  3. 3Save a version with a message that says what changed
  4. 4Bring a file back with git restore and undo a version with git revert

Goal: save versions with status, add, diff and commit, and undo an agent's change with git restore, without panic.

  1. 1/5

    In the folder

    The agent created or changed files. git status shows each one: "Untracked files" are the ones Git isn't tracking yet; "Changes not staged" are changes that haven't been set aside yet.

  2. 2/5

    Staged

    git add with the file name sets aside only that file for the next version (Git calls this staging). git diff --cached shows, line by line, what will go in.

  3. 3/5

    Version saved

    The commit staples together what you set aside. The message is the photo's caption: a verb and an object, like "Adds contact section". "update" says nothing a month from now.

  4. 4/5

    Go back

    Change not saved yet: git restore returns the file to the last saved version (and discards what changed). Version already saved: git revert creates a new version that undoes the earlier one, without erasing the history.

  5. 5/5

    The cycle with the agent

    Commit before you ask. The agent makes the change. You look with status and diff. Like it: add and commit. Don't like it: restore. Every good version becomes a point you can go back to.

Git runs only on your computer, with no internet. GitHub is another step, optional (lesson 8).

02 · From git init to your first undo

Click each step.

1. Start the history

Inside meu-primeiro-agente, git init creates the history. Never in your whole personal folder.

git config user.name and user.email, without --global, say who is saving, only in this project. The email appears in every version and is visible if the folder is published.

It answersInitialized empty Git repository in …\meu-primeiro-agente\.git\

2. Look first

git status tells you which step each file is at. Always run it before setting anything aside.

This is where the .gitignore from lesson 5 proves itself: the .env doesn't show up in the list.

Look forAGENTS.md, README.md, .gitignore, .env.example… and no .env.

3. Save

To learn, name the files in git add. The shortcut git add . sets aside everything that isn't ignored, including the personal note forgotten in the folder.

git log --oneline shows the short list of versions, one per line.

Good messageCreates README, AGENTS.md and a list of what not to keep

4. Undo

Only in the file, not saved: git restore file. In a saved version: git revert with the version's code, which shows up in the log.

Check the open file, not just the terminal's reply.

Erratum, not erasureThe revert fixes it and leaves all three versions in the history.

03 · The Git commands

In the meu-primeiro-agente folder. Replace whatever is between < >.

cmd · start and say who you are (only in this folder)
cd %USERPROFILE%\projetos\meu-primeiro-agente
git init
git config user.name "<Your Name>"
git config user.email "<your@email.com>"
git status
cmd · look, set aside and save the first version
git add README.md AGENTS.md .gitignore .env.example index.html
git diff --cached
git commit -m "primeira versão"
git log --oneline
cmd · after the agent changed something
git status
git diff
cmd · didn't like it: put the file back
git restore index.html
git status
cmd · like it? Save the new version
git add index.html
git commit -m "<o que mudou, com verbo>"
cmd · undo a version you already saved
git log --oneline
git revert <código da versão>
Simulation: illustrative example
On branch master
No commits yet
Untracked files:
  (use "git add <file>..." to include in what will be committed)
        .env.example
        .gitignore
        AGENTS.md
        README.md
        index.html

"Untracked files" = outside the history. The .env isn't in the list: the .gitignore worked.

  • Untracked files: files Git isn't tracking yet.
  • Changes to be committed: set aside, they go into the next version.
  • Changes not staged: changed, but not set aside.
  • nothing to commit, working tree clean: nothing has changed since the last version.
  • git init in your home folder: Git starts watching Documents, Downloads, everything. Run cd first and check the path.
  • Skipping Git: the agent's first bad change turns into manual rework.
  • "Please tell me who you are": the git config for name and email is missing.
