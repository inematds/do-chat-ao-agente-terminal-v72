Lesson 4 · 18 min

First the agent reads, then it changes

"Fix up the project" mixes diagnosis and change: if something goes wrong, you don't know which part it was. Separating reading from changing, giving the smallest permission that works and asking for a wrap-up that says what was checked turns the agent into someone you manage.

Start the lesson

In this lesson you will

  1. 1Ask for reading without editing and check the files used
  2. 2Authorize a small, named change
  3. 3Write an authorization in five parts
  4. 4Require the wrap-up: done, checked, pending

Goal: give the agent a scoped task, check what it read and changed, and ask for at least one fix.

  1. 1/5

    Inspect

    No file changes in this stage. Ask in so many words: without editing. And ask it to say which files it read, so you can compare with dir /b.

  2. 2/5

    Plan

    The list of what is missing is your reference. If it told you it didn't open a file, the plan doesn't know that content yet: say in your next request what it should rely on.

  3. 3/5

    Change

    You say which file can be created or changed. If the agent asks before editing, check that it's only that file and approve. If it's another one, refuse.

  4. 4/5

    Validate

    The last word is yours. Open the result and compare it with what you asked for. Ask for at least one correction: giving the task, checking it, and deciding is management.

  5. 5/5

    Using × managing

    Someone who uses asks and accepts. Someone who manages separates reading from changing, authorizes with a scope, and checks before approving. The difference is in the habit, not the tool.

It works the same in Claude Code and Codex: both read AGENTS.md and work in the folder where they were opened.

02 · Autonomy is authorization with a scope

Five parts that fit on a sticky note.

1. Goal and files

Say what to produce and what it can read. "Draft of the September report, only from the September spreadsheet."

A small folder, with only the task's material, already limits what it can reach.

ExampleGoal: index.html about me. Files: only AGENTS.md.

2. Actions and stopping point

Say which actions are authorized and which are forbidden: read and create, yes; delete and rename, no. Sending, publishing, and deleting are external actions: each one requires an explicit instruction.

The button existing is not permission. Say where it stops and waits for you.

StopHand in the draft and stop before sending.

3. Minimum permission

Reading files is low risk; writing, medium; running commands, high. Start with the most restricted option that gets the task done.

A written rule guides; what actually stops it is the program's permissions. In Codex, /permissions shows and changes what it can do.

Don'tRemove all the protections to get around an error.

4. Wrap-up

Always ask it to finish by saying what was done, how it was verified, and what is still pending.

That way the result becomes something you review, not something you have to take on faith.

03 · The requests, in order

Open the agent inside the folder (claude or codex) and paste one request at a time.

Request 1 · read only
Read AGENTS.md and README.md. Explain the project's purpose and list what is missing, without editing anything. At the end, say which files you used.
Request 2 · a change with a name and a stop
Read AGENTS.md. Create only index.html with a simple page about me, using what is there. Do not change or delete any other files.
At the end, tell me: what was done, how you checked it, and what is still pending.
cmd · check the change
dir /b
start index.html
Request 3 · the correction
Change the title to "<your title>" and add a contact section. Only in index.html.
Request 4 · the agent reads your files
Read the .txt files in the entradas folder and write saidas/resumo.md with 5 decisions and 5 pending items, citing which file each one came from.
cmd · a restore point before Git (lesson 6)
cd %USERPROFILE%\projetos
xcopy /e /i meu-primeiro-agente meu-primeiro-agente-antes
rem after the change, compare:
fc /n meu-primeiro-agente-antes\*.md meu-primeiro-agente\*.md
Simulation: illustrative example

Request 1: "The purpose is a page about Ana. Missing: the index.html, the format, and how to check it. Files read: AGENTS.md and README.md. I also looked at the file listing. Nothing was edited."

It explained, listed what is missing, and said what it read and what it did not read. No file changed.

  1. The files it says it read exist in the dir /b listing.
  2. After request 2, only index.html appeared.
  3. The page opens in the browser and you asked for a correction.
  4. In resumo.md, you found at least two of the quoted sentences in the original.
  • "Improve the page": produces a change you don't know how to check. Ask for a result you can see.
  • Approving without reading: the agent asks before editing precisely so you can see which file changes.
  • A quote that doesn't exist in the original: add the missing rule to AGENTS.md ("quote only sentences that exist in the file").
