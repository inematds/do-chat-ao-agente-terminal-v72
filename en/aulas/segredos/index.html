Lesson 5 · 14 min

Keep secrets out of the text

A key pasted into a document, a screenshot, or a request gives access to anyone who reads it, and it stays valid after the conversation ends. Separating the secret from everything else before saving the first version lets you share the folder without worry.

Start the lesson

In this lesson, you will

  1. 1.env stores the key; .env.example shows only the names
  2. 2.gitignore written before the first version
  3. 3Leaked? Replace the key at its source first
  4. 4The AI needs the variable name, not the value

Objective: create .env, .env.example, and .gitignore before the first commit, and know what to do if a key leaks.

Scroll down: each step below lights up its part of the diagram.

  1. 1/5

    .env

    Stores variables: a name, an equal sign, and a value. It is not a safe: it is not encrypted, and anyone who opens the file can read it. So keep it only on your machine and never put it in Git.

  2. 2/5

    .env.example

    The same names, with fake values. Anyone who gets the project can see what they need to fill in, but they do not get access to anything. Remember: anything ending in example is the example.

  3. 3/5

    .gitignore

    Each line is a pattern. .env matches the file; .env.* matches variants like .env.local; the line with ! makes an exception and puts .env.example back on the list of files to save.

  4. 4/5

    History

    .gitignore only applies to files Git has not saved yet. If .env is already in a commit, adding the line later does not remove it from the history. That is why the list comes before the first version.

  5. 5/5

    Ignore before the first commit

    The .env with the real value stays at home, .env.example can be shared, and .gitignore decides this before Git saves any version. Once the mailbag has left, crossing the paper off the list will not bring it back.

The AGENTS.md rule says: "Never write keys or passwords in a text file; keep them in .env."

02 · Four rules about secrets

Click each one.

1. A credential is the key to the room

A password, API key, and bot token let whoever has them act on behalf of your account, and you pay the bill.

Before sending a screenshot, check the corners of the screen: a visible password belongs to everyone who receives it.

Screenshot with password coveredThe same screen, with the password covered before sending.

2. AI needs the name

To help, AI almost always only needs to know that the variable exists, like TELEGRAM_BOT_TOKEN.

A real value does not belong in a request, course example, or file sent to AI unless needed.

The right requestThe bot token is in the TELEGRAM_BOT_TOKEN variable in .env.

3. The list before the version

Create .gitignore before the first git commit. It does not remove anything that is already in the history.

In the next lesson, git status is the proof: .env must not appear.

Checkgit status does not show .env.

4. Was it leaked?

If a key was published or pasted by mistake, the first fix is to revoke it on the site that created it and generate another. Deleting the message or line does not invalidate a copy someone has already seen.

Only then take care of the file and the history.

Order1. Revoke and replace it. 2. Clear the file.

03 · The three files

In the meu-primeiro-agente folder. The key is fake, for practice.

cmd · create the practice .env and .gitignore
cd %USERPROFILE%\projetos\meu-primeiro-agente
echo MINHA_CHAVE=teste123> .env
echo MINHA_CHAVE=preencha_localmente> .env.example
echo .env> .gitignore
echo .env.*>> .gitignore
echo !.env.example>> .gitignore
type .gitignore
.gitignore (what should be inside)
.env
.env.*
!.env.example
AGENTS.md · new rule
- Never write keys or passwords in a text file; keep them in .env.
- If you need a key, mention the variable name, never its value.
Simulation: illustrative example
C:\Users\ana\projetos\meu-primeiro-agente> type .gitignore
.env
.env.*
!.env.example

One > creates the file (or replaces its contents); two >> add a line at the end.

  • Space before >: echo .env > .gitignore writes ".env " with a trailing space. Type it without a space: echo .env> .gitignore.
  • Key in AGENTS.md “so the agent knows how to use it”: anything in text can end up on GitHub.
  • .gitignore after the commit: .env stays in the old version.
