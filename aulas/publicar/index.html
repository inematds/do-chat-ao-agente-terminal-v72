Aula 8 · 20 min

Página no ar e o mesmo projeto numa VPS

Salvar, enviar e pôr no ar são três passos e três decisões. Com uma chave SSH e o gh, você envia o projeto ao GitHub, publica a página com um endereço que abre no celular e leva a mesma pasta para uma VPS, onde o agente trabalha mesmo com o seu computador desligado.

Começar a aula

Nesta aula você vai

  1. 1Criar a chave SSH e entregar só a pública
  2. 2Criar o repositório, publicar no Pages e a rotina do push
  3. 3Conferir destino, estado, versões e segredos antes de enviar
  4. 4Entrar na VPS, clonar o projeto e trazer o que mudou

Objetivo: ligar o terminal ao GitHub com chave SSH, publicar a página no GitHub Pages e clonar o projeto numa VPS.

01 · Três lugares, um projeto

O GitHub é a ponte entre o seu computador, a página e a VPS.

1/5

Seu computador

A chave privada nunca sai daqui. O commit guarda a versão só no seu computador; nada vai para a internet até você decidir enviar.

Role a página: cada etapa abaixo acende a sua parte do diagrama.

  1. 1/5

    Seu computador

    A chave privada nunca sai daqui. O commit guarda a versão só no seu computador; nada vai para a internet até você decidir enviar.

  2. 2/5

    GitHub

    O push envia as versões. Repositório público: qualquer pessoa vê (e é o que a página grátis exige). Privado: só você e quem você convidar. Você escolhe na hora de criar.

  3. 3/5

    GitHub Pages

    Pôr no ar é uma etapa a mais. Ligado o Pages, cada push atualiza a página em alguns minutos, com um endereço que abre no celular.

  4. 4/5

    VPS

    Uma sala alugada: o provedor entrega a máquina; usuários, atualizações e programas são com você. Você entra pelo ssh, navega com os nomes do Linux e traz o projeto do GitHub.

  5. 5/5

    Salvar, enviar, pôr no ar

    O commit fica no seu computador, o push leva ao GitHub e o Pages põe no ar. A VPS pega a mesma versão com git pull. Cada passo é uma decisão sua, com conferência própria.

A chave pública (.pub) é o cadeado: vai para o GitHub e para a VPS. A privada é a chave do chaveiro: fica com você.

02 · Do commit à página no ar

Clique em cada etapa.

1. Chave SSH

ssh-keygen já vem no Windows 10 e 11. Ele faz três perguntas: onde guardar e uma senha extra, duas vezes. Enter nas três serve para treino.

Ficam dois arquivos em %USERPROFILE%\.ssh: id_ed25519 (privada, nunca sai dali) e id_ed25519.pub (pública).

Perguntou Overwrite?Você já tem uma chave: responda n e use a que existe.

2. Ligar o gh

Responda: GitHub.com → SSH → escolha id_ed25519.pub → Login with a web browser. Copie o código, cole no navegador e autorize.

ssh -T git@github.com testa a chave; na primeira vez responda yes.

RespostaHi SEU-USUARIO! You've successfully authenticated.

3. Conferir antes de enviar

Destino: git remote -v mostra para onde vai. Estado: git status limpo. Versões: git log --oneline mostra o que iria. Segredos: nenhum .env na lista.

Depois de enviado, o conteúdo fica com quem tem acesso ao destino.

PúblicoQualquer pessoa vê. Nada de rascunho pessoal nem chave.

4. Na VPS

ssh root@IP-DA-VPS abre o terminal da VPS na sua janela. O começo da linha muda e termina em # ou $: olhe sempre em que máquina está antes de cada comando.

Lá: ls no lugar de dir, pwd no lugar de cd sozinho, e maiúscula importa.

Regra da segunda sessãoMudou o jeito de entrar? Teste numa janela nova antes de fechar a que funciona.

03 · Os comandos, na ordem

Troque Seu Nome, seu@email.com, SEU-USUARIO e IP-DA-VPS pelos seus.

cmd · quem é você no Git (para todos os projetos)
git config --global user.name "Seu Nome"
git config --global user.email "seu@email.com"
git config --global --list
cmd · a chave SSH
ssh-keygen -t ed25519 -C "seu@email.com"
explorer %USERPROFILE%\.ssh
cmd · ligar o gh à sua conta
gh auth login
ssh -T git@github.com
cmd · criar o repositório e enviar
cd %USERPROFILE%\projetos\meu-primeiro-agente
git status
git branch -M main
gh repo create meu-primeiro-agente --public --source=. --push
cmd · ligar o GitHub Pages
gh api repos/{owner}/{repo}/pages -X POST -f "source[branch]=main" -f "source[path]=/"
cmd · a rotina de todo dia
git status
git add .
git commit -m "o que mudou"
git push
VPS (Linux) · entrar, clonar e atualizar
ssh root@IP-DA-VPS
mkdir -p ~/projetos
cd ~/projetos
apt update && apt install -y git
git clone https://github.com/SEU-USUARIO/meu-primeiro-agente.git
cd meu-primeiro-agente
ls
git pull
exit
VPS (Linux) · o agente no servidor
curl -fsSL https://claude.ai/install.sh | bash
cd ~/projetos/meu-primeiro-agente
claude
Simulação: exemplo ilustrativo
C:\Users\ana> ssh -T git@github.com
Hi ana-exemplo! You've successfully authenticated, but GitHub does not provide shell access.
C:\Users\ana\projetos\meu-primeiro-agente> gh repo create meu-primeiro-agente --public --source=. --push
✓ Created repository ana-exemplo/meu-primeiro-agente on GitHub

Alguns minutos depois de ligar o Pages, a página abre em https://ana-exemplo.github.io/meu-primeiro-agente/.

  • "nothing to commit": a pasta está vazia ou já salva. Confira com dir e git log --oneline.
  • "Name already exists": já existe um repositório com esse nome na sua conta. Escolha outro.
  • Push recusado com "fetch first": o repositório mudou em outro lugar. git pull e depois git push.
  • "No such file or directory" na VPS: confira maiúsculas e use Tab para completar.

Alguém pediu a sua chave "para configurar o acesso": só o id_ed25519.pub. O id_ed25519, sem .pub, nunca sai do seu computador.

04 · Ensaie: o projeto na VPS

Mesma navegação, outros nomes. Olhe o começo da linha.

Missões

  1. 1Entre na VPS como root (o IP de exemplo é 203.0.113.10).
  2. 2Pergunte onde você está (no Linux é pwd).
  3. 3Crie a pasta de projetos (mkdir -p ~/projetos).
  4. 4Entre nela.
  5. 5Traga o projeto do GitHub (usuário ana-exemplo).
  6. 6Entre na pasta e liste o conteúdo (dois comandos: primeiro o cd).
  7. 7Liste o que veio (no Linux é ls).
  8. 8Você mudou algo no Windows e deu push. Traga a mudança.
  9. 9Saia da VPS.

Pronto quando: a resposta começa com "Hi" seguido do seu usuário do GitHub.
E16 · Página no ar
20 min
Faça a conferência de quatro pontos, crie o repositório público, ligue o Pages e depois mude algo e rode a rotina add, commit e push.
Pronto quando: a página abre no celular em https://SEU-USUARIO.github.io/meu-primeiro-agente/ e a mudança aparece depois do push.
E17 · O mesmo projeto na VPS
30 min
Numa VPS Ubuntu contratada com a sua chave pública, entre com ssh, clone o projeto, mude algo no Windows, dê push e traga com git pull.
Pronto quando: ls na VPS mostra os arquivos e o git pull trouxe a mudança feita no Windows.
